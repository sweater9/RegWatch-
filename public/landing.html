What it does

Everything you need to track regulatory change

RegWatch aggregates updates from the world's leading financial crime regulators into a single, chronological feed — so you never miss a guidance, paper, or rulemaking.

Unified chronological feed

All regulatory updates in a single timeline, sorted by date. No more checking twenty websites individually.

Multi-jurisdiction coverage

UK FCA, US SEC, Bank of England, BIS, BaFin, DOJ, FINMA, AUSTRAC, Federal Register (FinCEN, OFAC, OCC), FATF, EBA, MAS, and seven UAE regulators — all in one place.

Automated refresh cycle

A GitHub Action runs every 6 hours, fetching all sources and updating the feed. Set it up once and forget about it.

Resilient by design

Each source is fetched independently. A temporarily unavailable source never blocks the remaining ones — failures are reported transparently.

Static & serverless

Served as a static site with no backend at request time. No server costs, no infrastructure to manage, no API keys to rotate.

Extensible source system

Add new sources in minutes. Drop an RSS feed into the config or write a small module for JSON API sources — the pattern is documented and consistent.

How it works

Automated from source to screen

A GitHub Action handles the entire pipeline — fetching, parsing, and deploying. No manual intervention required.

STEP 01

Build feed

A GitHub Action runs build-feed.js, which fetches all configured sources in parallel.

STEP 02

Parse & aggregate

A minimal RSS/Atom parser processes each source. Results are merged into a single chronological feed.json file.

STEP 03

Commit changes

If the feed changed, the workflow commits the updated feed.json back to the repository.

STEP 04

Deploy

The static site is deployed to GitHub Pages (and optionally Cloudflare Workers). The updated feed goes live automatically.

# Run locally — no server needed
npm run build-feed

# Output
public/feed.json  # Generated feed data
public/index.html # Static UI reads feed.json client-side

# Or serve locally
npx serve public/

Deployment

Deploy anywhere static

Two deployment targets are built in. Both serve the same static site — pick what fits your infrastructure.

Primary

GitHub Pages

The default deployment target. Enable GitHub Pages once under Settings, and the included workflow handles everything — the site updates on schedule and redeploys automatically.

Settings → Pages → Source: GitHub Actions

Optional

Cloudflare Workers

Mirrors the same static site via Cloudflare's static-assets configuration. Activates automatically when repository secrets are set. Without secrets, this step is skipped and GitHub Pages continues normally.

Requires: CLOUDFLARE_API_TOKEN, CLOUDFLARE_ACCOUNT_ID
